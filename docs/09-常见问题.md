# 09 · 常见问题

> 按"看到什么"查。每条给：现象 → 原因 → 处理。

---

## 一、启动阶段

### 启动报 `No qualifying bean of type 'javax.sql.DataSource'`

**原因**：只引了 `spring-boot-starter-web`，没有 JDBC 实现与连接池。

**处理**：`server/pom.xml` 已有 `spring-boot-starter-jdbc`，确认没被删；切库时还要有对应驱动（h2 / mysql-connector-j / postgresql 均已引入 runtime 范围）。

### 启动报 `NULL not allowed for column "XXX_ID"`

**原因**：主键字段加了 `fixed = true`，iPage 因此判定"主键由外部固定提供"，**跳过了自动补 UUID**。

**处理**：去掉 `@ModelField` 上的 `fixed = true`。String 主键在插入时由引擎自动生成 UUID，
只有显式给主键赋了非法值（空串、超长）才会报这个错。

### 启动报 `JAVA_HOME is not defined correctly` / `We cannot execute .../bin/bin/java`

**原因**：`JAVA_HOME` 被设成了 `<JDK>/bin`，而 Maven Wrapper 会在后面再拼一个 `/bin`。

**处理**：
```bash
export JAVA_HOME="/c/Program Files/Java/jdk-22"     # 指向 JDK 根目录
```

### 启动报 `Unable to rename ... .jar to ....jar.original`

**原因**：Windows 上旧进程还占着 jar 文件。

**处理**：先停掉正在运行的 `java -jar`，再 `package`。

### 端口 8080 被占用

```bash
# Windows
netstat -ano | findstr :8080
# Linux / macOS
lsof -i :8080
```
换端口：`--server.port=8081`。

### 启动日志没有 `CREATE TABLE`，但库是空的

**原因**：`ims.sync-schema=false`，或模型不在 `com.rabbitc.ims.model` 包下。

**处理**：检查配置；确认模型类有 `@ModelClass` 且在正确包内。

## 二、登录与权限

### 一直 401 `账号或密码不正确`

- 账号是否存在（注意大小写、前后空格）；
- 是否刚改过密码：改密会让 `token_version + 1`，**旧令牌全部失效**，必须用新令牌；
- 是否换过 `IMS_SECRET`：换了之后所有旧令牌验签失败，需重新登录；
- 库是不是被重建过（演示数据重新生成，密码回到 `admin123`）。

### 登录成功但立刻又跳回登录页

前端 `loadMe()` 失败会清令牌。看浏览器 Network 里 `/api/auth/me` 的状态码：
- 401 → 令牌没存上（`localStorage['ims_token']`）；
- 403 → 账号被停用。

### 403 `没有查看「用户」的权限`

这是**设计如此**。`User` 模型 `look = ADMIN`，等级 < 3 的账号看不到。
换 `admin` 登录，或调整该模型的 `look`（不推荐，用户表含敏感字段）。

### 403 `当前账号未分配部门，无法查看部门数据`

角色数据范围是 `DEPT`，但用户 `dept_id` 为空。

**处理**：给用户分配部门；或把角色改成 `ALL`/`SELF`。

### 列表里数据比预期少

数据范围在起作用：

| 角色范围 | 实际过滤 |
| --- | --- |
| `SELF` | `create_by = 我` |
| `DEPT` | `dept_id = 我的部门` |

用 `admin`（`ALL`）对比一下就能确认。

### 管理员改了权限，用户没变化

- 前端需要刷新（`/api/auth/me` 重新拉一次）；
- 权限是每次请求重读库的，**不需要重新登录**，但页面上的按钮显隐依赖前端缓存的 `auth.user`。

## 三、CRUD 与数据

### 新增报 `员工 不存在：not-a-uuid`（404）

路径里的 id 不是合法 UUID。主键已是 UUID，旧的数字 id（如 `/1`）查不到了。
**从自增主键升级过来时必须重建库**。

### 新增报 400 `请求体不是合法的 JSON 或字符编码不是 UTF-8`

在 Windows Git Bash 里 `curl -d '{"name":"中文"}'` 会传出 GBK 字节。

**处理**：把 body 写进文件再 `--data-binary @body.json`，或显式声明 `charset=utf-8`。

### 中文搜索搜不到

URL 里的中文没做百分号编码。

```bash
curl -s "localhost:8080/api/models/employee?kw=%E8%8B%8F" -H "Authorization: Bearer $TOKEN"
```

### 前端表单里关联下拉是空的 / 选了不生效

- 下拉选项来自被关联表，**当前用户对被关联表没有查看权限时**选项会是空；
- 如果之前把 `ASSOCIATION_ID` 的值转成了 `Number`，UUID 会变成 `NaN`，选择静默失效。
  代码里应保持字符串（`DataForm.vue` 已修正）。

### 字段不显示

- `look = false`（服务端不下发）；
- `lookPermission` 高于当前等级；
- 前端缓存了旧 schema —— 刷新页面。

### 改不了某个字段

`editPermission = FORBIDDEN`，或该字段 `fixed = true`，或类型是 `AGGREGATION`（不落库）。

## 四、界面

### 每个页面控制台都有一条 500

历史问题，原因是浏览器自动请求 `/favicon.ico`，被兜底异常处理器记成 500。
现已修复：新增 `web/public/favicon.svg`，并让 `NoResourceFoundException` 返回 404 且不记 ERROR。

### 深色模式下文字看不清

组件里写死了颜色。所有颜色必须走 `styles.css` 的 CSS 变量（`--text` / `--bg` / `--panel` …）。

### 刷新后 404

用的是 hash 路由（`/#/m/employee`），正常不会 404。
如果改成了 history 路由，需要在 Nginx 加 `try_files $uri $uri/ /index.html;`。

### 列设置保存后换个人登录也生效了

不应该。`sys_view_config` 按 `owner_id` 隔离，接口只读写本人行。
如果出现串数据，检查 `ViewConfigController.find()` 是否漏了 `ownerId` 条件。

## 五、AI

### 状态显示 `enabled:false`

```bash
export IMS_AI_ENABLED=true
export IMS_AI_KEY=sk-xxx
```
改完要**重启**（配置是启动时读的）。

### `ready:false`，`reason` 提示缺 Key

`IMS_AI_KEY` 为空或只有空格。

### AI 说"我没有查询数据的工具"

- `ims.ai.allow-tools=false`；
- 或本次请求传了 `allowTools:false`；
- 或用户没有 `ai:use` 权限（`/api/ai/chat` 会直接 403）。

### MCP 服务 `ok:false`

按 `error` 判断：

| 错误 | 原因 |
| --- | --- |
| `启动命令必须是 JSON 数组` | `command` 填了普通字符串 |
| `Cannot run program "python"` | 本机没有 python，或不在 PATH；换绝对路径 |
| `No such file or directory` | 脚本路径不对；相对路径是相对**进程工作目录**，建议用绝对路径 |
| 超时 | `timeoutMs` 太小，或脚本没实现 `initialize` |

### 改了 MCP/Skill 配置没生效

- 通过界面改会发 `AiConfigChangedEvent` → `invalidateAll()`；
- 直接改数据库不会触发，调用 `POST /api/ai/reload`（需要 `ai:manage`）。

### Skill 加载失败

看 `/api/ai/status` 的 `skillErrors`。常见原因：`directory` 指向的目录里没有 `SKILL.md`，
或路径是相对路径（会按进程工作目录解析）。

## 六、数据库

### H2 提示 `Database may be already in use`

同一份 `./data/ims` 被两个进程打开。

**处理**：停掉另一个进程；或确认连接串里的 `AUTO_SERVER=TRUE` 还在（允许多进程共享）。

### 切到 MySQL 后表名报大小写错误

Linux 上 MySQL 默认 `lower_case_table_names=0`，表名区分大小写。本项目表名全小写，一般没问题；
如果手工建过混合大小写的表，需要统一。

### PostgreSQL 报 `column "xxx" does not exist`

Postgres 方言会给标识符加双引号，未加引号的列名会被折叠成小写。
所有 SQL 的标识符都必须走 `dialect.quote(...)`（见 AGENTS.md 2.1）。

### 改字段类型不生效

iPage 的 schema 同步**只建表、只补列**，不改类型、不删列。

**处理**：手工执行 `ALTER TABLE`，并同步修改模型类。

## 七、构建

### 前端 `npm install` 后 esbuild 报错

npm 11+ 会拦截依赖的 postinstall 脚本（如 `esbuild`）。

**处理**：
```bash
npm approve-scripts --allow-scripts-pending
# 或
npm install --foreground-scripts
```
（本项目实测即使不跑该脚本也能正常 `vite build`，因为 esbuild 的平台二进制是可选依赖。）

### `npm run build` 报 `Could not resolve ...`

检查 import 路径大小写（Linux 区分大小写），以及文件是否真的存在。

### 后端起来了但访问 / 是 404

`server/src/main/resources/static/` 是空的 —— 前端产物没拷进去，或 `package` 在拷贝之前跑的。

```bash
ls server/target/classes/static/index.html
unzip -l server/target/ims-server-1.0.0.jar | grep static/index.html
```

## 八、还是解决不了怎么办

按这个顺序收集信息（80% 的问题在这一步就能定位）：

1. **完整堆栈**：`journalctl -u ims -n 200` 或控制台输出，找第一个 `Caused by`；
2. **实际 SQL**：临时开 `logging.level.com.rabbitc.ipage=debug`；
3. **请求与响应**：浏览器 DevTools → Network，看请求体、状态码、响应 `message`；
4. **身份**：`GET /api/auth/me` 看 `level` / `dataScope` / `permissions` 是否符合预期；
5. **库里的真实数据**：直接查表，确认不是"数据本身就不对"。
