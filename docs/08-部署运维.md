# 08 · 部署运维

---

## 1. 构建产物

```bash
# 一条命令：前端构建 → 拷进后端 static → 打成可执行 jar
cd web && npm install && npm run build && cd ..
rm -rf server/src/main/resources/static && mkdir -p server/src/main/resources/static
cp -r web/dist/* server/src/main/resources/static/

export JAVA_HOME=/path/to/jdk-17        # 指向 JDK 根目录，不是 bin
./mvnw -pl server -am package -DskipTests

ls -lh server/target/ims-server-1.0.0.jar    # 约 28 MB（含前端与全部依赖）
```

产物是 **Spring Boot 可执行 jar**：内嵌 Tomcat + 前端静态资源，单文件部署。

> `-pl server -am` 表示"只构建 server 及其依赖模块"（`libs/ipage`、`libs/embed-ai-chat`）。
> 单独 `./mvnw package` 会构建全部三个模块，结果一样，只是慢一点。

## 2. 启动

```bash
# 最小启动（H2 文件库，数据在 ./data/ims.mv.db）
java -jar ims-server-1.0.0.jar

# 指定端口 / 外部配置
java -jar ims-server-1.0.0.jar --server.port=9000 --spring.config.additional-location=./conf/
```

首次启动会：
1. 按模型建表（`ims.sync-schema=true`）；
2. 用户表为空时写入演示数据（`ims.seed=true`）；
3. 释放内置 Skill 到 `data/ai/skills/`。

## 3. 生产环境必做的五件事

### 3.1 换掉签名密钥

```bash
export IMS_SECRET=$(openssl rand -base64 32)
```

不换的后果：任何人都能用仓库里公开的默认密钥**伪造令牌**，等同于没有登录。

### 3.2 改掉演示账号密码

`admin/admin123`、`manager/manager123`、`staff/staff123` 是公开的。
登录后到「个人设置」改密码，或直接删掉不用的账号。

### 3.3 关掉自动建表与种子数据

```yaml
ims:
  seed: false
  sync-schema: false
```

生产环境的 DDL 应该走变更流程，不该由应用启动时自动执行。

### 3.4 换掉 H2

H2 是单文件嵌入式库，适合开发和演示；生产请用 MySQL 或 PostgreSQL。

```bash
java -jar ims-server-1.0.0.jar --spring.profiles.active=mysql
# 凭据用环境变量：MYSQL_USER / MYSQL_PASSWORD
```

先建库：

```sql
CREATE DATABASE ipage_ims DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

> MySQL 8 建议 `utf8mb4`；`utf8` 存不了 emoji。

### 3.5 只暴露必要端口

默认只监听所有网卡的 8080。生产建议：

```bash
java -jar ims-server-1.0.0.jar --server.address=127.0.0.1 --server.port=8080
```

再由 Nginx 反代并终止 TLS。

## 4. Nginx 反代示例

```nginx
server {
    listen 443 ssl http2;
    server_name ims.example.com;

    ssl_certificate     /etc/letsencrypt/live/ims.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ims.example.com/privkey.pem;

    client_max_body_size 10m;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # AI 对话可能较慢，超时放宽
        proxy_read_timeout 120s;
    }
}

server {
    listen 80;
    server_name ims.example.com;
    return 301 https://$host$request_uri;
}
```

前端用 hash 路由（`/#/m/employee`），**不需要**配置 SPA fallback（`try_files ... /index.html`）。

## 5. systemd 服务

```ini
# /etc/systemd/system/ims.service
[Unit]
Description=iPage IMS
After=network.target

[Service]
Type=simple
User=ims
WorkingDirectory=/opt/ims
Environment="IMS_SECRET=换成你的密钥"
Environment="IMS_AI_ENABLED=true"
Environment="IMS_AI_KEY=sk-xxx"
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/ims/ims-server-1.0.0.jar \
          --spring.profiles.active=mysql
Restart=on-failure
RestartSec=5
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now ims
journalctl -u ims -f
```

> `SuccessExitStatus=143` 是因为 Spring Boot 优雅停机收到 SIGTERM（143）会正常退出，
> 不加会被 systemd 判为失败。

## 6. Docker（可选）

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY server/target/ims-server-1.0.0.jar app.jar
ENV TZ=Asia/Shanghai
EXPOSE 8080
ENTRYPOINT ["java","-XX:MaxRAMPercentage=75","-jar","/app/app.jar"]
```

```bash
docker build -t ipage-ims:1.0.0 .
docker run -d --name ims -p 8080:8080 \
  -e IMS_SECRET=... -e IMS_AI_ENABLED=true -e IMS_AI_KEY=... \
  -v /data/ims:/app/data \
  ipage-ims:1.0.0
```

> 数据库别放容器里。用外部 MySQL/PG，容器只管应用。

## 7. 备份

| 内容 | 位置 | 方式 |
| --- | --- | --- |
| 业务数据 | 数据库 | `mysqldump` / `pg_dump`（H2 则停服后拷 `data/`） |
| AI 工作目录 | `data/ai/`（Skill 释放位置） | 文件备份，可重建，非关键 |
| 配置密钥 | 环境变量 | 放密钥管理系统，**不要进 git** |

MySQL 每日全量示例：

```bash
mysqldump -u root -p --single-transaction --routines ipage_ims \
  | gzip > /backup/ims-$(date +%F).sql.gz
```

> 主键是 UUID，所以**跨环境导入不会撞主键**，备份可以直接灌进测试库做演练。

## 8. 升级步骤

```bash
# 1. 备份
mysqldump ... > backup.sql

# 2. 停服
systemctl stop ims

# 3. 换 jar
cp ims-server-1.1.0.jar /opt/ims/ && ln -sfn ims-server-1.1.0.jar /opt/ims/app.jar

# 4. 启动并观察日志
systemctl start ims && journalctl -u ims -f

# 5. 验证
curl -s localhost:8080/api/health
```

**注意 DDL 变化**：
- 新增字段/表：`sync-schema=true` 会自动补；设为 `false` 时需手工执行 DDL。
- **改列类型 / 删列 / 改主键类型（如自增→UUID）**：iPage 不会处理，必须写迁移脚本。
  从旧版本升级到 UUID 主键属于**不兼容变更**，需要重建库或写数据迁移。

## 9. 监控与排查

| 关注点 | 怎么看 |
| --- | --- |
| 存活 | `GET /api/health`（免认证，适合探针） |
| 启动是否正常 | 日志里 `表结构同步完成` + `演示数据完成` |
| 慢查询 | `logging.level.com.rabbitc.ipage=debug` 打印每条 SQL |
| 权限问题 | 日志无记录，直接看 `403` 响应的 `message` |
| AI 问题 | `GET /api/ai/status` 的 `reason` / `mcp[].error` |
| 审计 | 「审计日志」页或 `sys_audit_log` 表 |

JVM 参数建议（小规模）：

```
-Xms256m -Xmx512m -XX:+UseG1GC -XX:MaxRAMPercentage=75
```
