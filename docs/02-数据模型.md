# 02 · 数据模型

> 一张表 = 一个类。本文讲清：注解怎么写、每种字段类型的语义、UUID 主键为什么这么定、
> 以及建表/改表的边界在哪里。

---

## 1. 模型类的三条铁律

1. **字段必须是 `public`**。iPage 用反射直接读写字段，不走 getter/setter，也不需要 Lombok。
2. **类上加 `@ModelClass`，主键字段加 `type = FieldType.MODEL_ID`**，缺一个就不算模型。
3. **类必须放在 `com.rabbitc.ims.model` 包下**。`ModelRegistry` 只扫描这个包。

模型 key 由类名推导：`Employee → employee`、`AiMcpServer → aiMcpServer`，
这就是 URL 里的 `{key}` 和前端路由 `/m/employee` 的来源。

---

## 2. `@ModelClass` 属性

| 属性 | 必填 | 默认 | 作用 |
| --- | --- | --- | --- |
| `name` | ✅ | — | 中文名，用于菜单、标题、错误提示 |
| `table` | 建议 | 类名转下划线 | 物理表名。**分组也由它决定**：`ims_`→业务数据，`sys_`→系统管理，`ai_`→智能助手；其他前缀（如论文域的 `th_`）落到默认的「业务数据」 |
| `look` | | `LEAST` | 查看整张表需要的最低等级 |
| `edit` | | `LEAST` | 新增/修改需要的最低等级 |
| `delete` | | `LEAST` | 删除需要的最低等级 |
| `icon` | | `fa-user-friends` | 侧边栏图标（Font Awesome 类名） |
| `text` | | 类名 | 显示模板，如 `${name}`、`${code}-${name}`，用于下拉框与 `_display` |

> `LEAST` = `Integer.MIN_VALUE`，即"人人满足"。**新增模型时请显式写上三个权限**，
> 默认全开容易被忽略成越权入口。

---

## 3. `@ModelField` 属性

| 属性 | 默认 | 作用 |
| --- | --- | --- |
| `column` | 必填 | 列名 |
| `text` | 空 | 中文标签 |
| `type` | `STRING` | 字段类型，见第 4 节 |
| `order` | 0 | 表格列顺序与表单顺序 |
| `look` | `true` | 是否在表格/表单/详情中可见。`false` 时仍参与查询（密码用） |
| `lookPermission` | `INHERIT` | 字段级查看权限，默认继承模型的 `look` |
| `editPermission` | `INHERIT` | 字段级编辑权限；`FORBIDDEN` 表示任何请求体都改不了 |
| `fixed` | `false` | 禁止新增/修改。**主键不要设这个**（见 5.2） |
| `byModel` | `Object` | 关联/聚合指向的模型类 |
| `byEnum` | `Enum` | 枚举字段的枚举类 |
| `function` | `COUNT` | 聚合函数 |
| `useRelatedForeignKey` | `false` | 聚合时是否借子表外键反查（见 4.6） |

## 4. 字段类型语义

### 4.1 `MODEL_ID` —— 主键
```java
@ModelField(column = "emp_id", type = FieldType.MODEL_ID, text = "ID", order = 1)
public String id;
```
- 类型必须是 `String`（UUID）；
- 只做 `EQ` / `NE` 查询；
- **不要加 `fixed = true`**。

### 4.2 `ASSOCIATION_ID` —— 外键列
```java
@ModelField(column = "dept_id", type = FieldType.ASSOCIATION_ID, byModel = Department.class,
        text = "部门", order = 5)
public String deptId;
```
落库的是被关联表的主键。前端渲染成下拉框（选项来自被关联表）。

### 4.3 `ASSOCIATION_MODEL` —— 关联对象
```java
@ModelField(column = "dept_id", type = FieldType.ASSOCIATION_MODEL, byModel = Department.class,
        text = "部门", order = 6)
public Department dept;
```
**不落库**，查询时由 iPage 用 LEFT JOIN 填充。响应里变成 `{"id":"...","label":"技术部"}`，
`label` 来自 `Department` 的 `@ModelClass(text="${name}")`。

> 二者**共用同一个 `column`**：一个管写（外键值），一个管读（对象）。必须成对出现。

### 4.4 `ENUM`
```java
@ModelField(column = "emp_status", type = FieldType.ENUM, byEnum = RecordStatus.class, text = "状态")
public RecordStatus status = RecordStatus.ENABLED;
```
- 枚举常量用 `@ModelEnum(text = "中文")` 标注；
- 响应同时给出 `status`（枚举名 `"ENABLED"`）与 `statusText`（中文 `"启用"`），
  前端显示 `statusText`、筛选传 `status`；
- **枚举不要存序号**，iPage 存的是 `name()`，改名会破坏历史数据的语义。

### 4.5 基础类型

| Java 类型 | 建议 `type` | 生成的列 | 说明 |
| --- | --- | --- | --- |
| `String` | `STRING` | `VARCHAR(255)` | 默认类型 |
| `Integer` / `Long` | `NUMBER` | `INT` / `BIGINT` | 用于排序号、数量 |
| `BigDecimal` | `NUMBER` | `NUMERIC(18,4)` | 金额，**不要用 double** |
| `LocalDate` | `DATE` | `DATE` | 响应格式 `yyyy-MM-dd` |
| `LocalDateTime` | `DATE` | `TIMESTAMP` | 响应格式 `yyyy-MM-dd HH:mm:ss` |
| `Boolean` | `BOOLEAN` | `BOOLEAN` / `TINYINT(1)` | |

### 4.6 `IMAGE` —— 图像
```java
// 引用形态：存一个字符串，三种来源都兼容
@ModelField(column = "avatar", type = FieldType.IMAGE, text = "头像")
public String avatar;
// 二进制形态：图像直接进 SQL（BLOB），如 SysFile.fileData
@ModelField(column = "file_data", type = FieldType.IMAGE, text = "内容")
public byte[] fileData;
```
- `String` 形态存**引用**：相对链接（`/api/files/<id>/raw`，本系统文件接口）、
  绝对链接（`https://...`）、`data:image/...;base64,` 内联 URI 均可；
- `byte[]` 形态把二进制**直接写进 SQL**，列类型由方言决定：
  H2 `BLOB` / MySQL `MEDIUMBLOB` / PostgreSQL `BYTEA`，读取时原样转回 `byte[]`；
- 只支持 `EQ` / `NE` / `IS_NULL` / `IS_NOT_NULL`，不做模糊匹配（二进制列上 LIKE 无意义）；
- 前端表格渲染缩略图、表单渲染「预览 + 上传 + 手填链接」控件（`DataForm` 已内置）；
- 大图建议走 `/api/files` 上传后引用相对链接，`String` 列是 `VARCHAR(255)`，`data:` URI 过长会被截断。

### 4.7 `AGGREGATION` —— 不落库的统计列

`Department` 里的"人数"：

```java
@ModelField(column = "employee_id", type = FieldType.AGGREGATION, byModel = Employee.class,
        function = SqlFunction.COUNT, useRelatedForeignKey = true, text = "人数", order = 7)
public Long employeeCount;
```

- `byModel = Employee.class`：去员工表数；
- `useRelatedForeignKey = true`：按"员工表的 `dept_id` 指向本行"来分组，
  而不是按 `Department` 自己的 `employee_id` 列（这列并不存在）；
- 结果列类型是 `Long`，但**不能手动赋值**，每次查询由 SQL 算出来；
- 前端可排序、可显示，但不可编辑。

## 5. 主键：为什么是 UUID

### 5.1 三个理由

| 理由 | 说明 |
| --- | --- |
| 不可枚举 | 自增主键的 `/api/models/employee/1` 可以被顺序遍历，泄露数据量、便于爬取 |
| 可离线生成 | 主键在插入前就已确定，批量导入、跨库迁移、未来分库都不需要改造 |
| 合并安全 | 开发库、测试库的数据互相导入不会撞主键 |

代价：主键列 `VARCHAR(255)`，索引比 `BIGINT` 大。管理系统量级可以忽略。

### 5.2 必须知道的三个后果

**① 插入时由引擎自动生成。** `String` 主键数据库不会自增，因此 iPage 的 `insert`
在写入前检查主键：**为空自动生成 UUID v4，已有值一律保留**；整数主键仍走数据库自增。
业务代码直接插入即可，显式赋值（关联表装配等场景）也允许：

```java
sql.insert(entity);        // 主键为空时引擎自动补 UUID
String id = entity.id;     // 插入后即可拿到
```

**② 主键不能加 `fixed = true`。** 加了会让 iPage 认为主键由外部固定提供，插入直接失败。
主键的防改写已经由 `CrudService.applyBody()` 跳过 `MODEL_ID` 保证，不需要 `fixed`。

**③ 所有外键也是 `String`。** `deptId`、`createBy`、`assigneeId`、`keeperId` 等一律 `String`，
接口路径变量也用 `String` 接（用 `Long` 会在参数绑定阶段就 400）。

## 6. 校验注解

```java
@ValidatorNotNull(message = "部门名称不能为空")
@ValidatorLength(min = 2, max = 64, message = "长度需在 2–64 之间")
@ValidatorPattern(regexp = "[A-Za-z0-9_]{3,32}", message = "只能字母数字下划线")
```

- 在 `insert` / `update` 时由 iPage 执行，抛 `CheckerException`；
- `CrudService` 已捕获并转成 400 + 中文提示；
- 前端 `DataForm.vue` 也做了一遍（`required` / `maxLength` / `pattern`），
  为了即时反馈；**服务端校验才是唯一的真相**，前端可以绕过。

## 7. 当前数据模型

### 7.1 业务数据

| 模型 | 表 | 说明 | 关联 |
| --- | --- | --- | --- |
| `Department` | `ims_department` | 部门 | 聚合员工数、资产数 |
| `Employee` | `ims_employee` | 员工 | → 部门；`createBy` → 用户 |
| `Asset` | `ims_asset` | 资产 | → 部门、→ 员工（保管人） |
| `Ticket` | `ims_ticket` | 工单 | → 部门、→ 用户（处理人） |

### 7.2 系统管理

| 模型 | 表 | 说明 |
| --- | --- | --- |
| `User` | `sys_user` | 用户（密码散列、令牌版本） |
| `Role` | `sys_role` | 角色（等级 + 数据范围） |
| `Permission` | `sys_permission` | 权限点 |
| `UserRole` | `sys_user_role` | 用户-角色关联（**不暴露 CRUD**） |
| `RolePermission` | `sys_role_permission` | 角色-权限关联（**不暴露 CRUD**） |
| `AuditLog` | `sys_audit_log` | 审计日志（只读） |
| `ViewConfig` | `sys_view_config` | 界面配置（**走独立接口**，按归属用户隔离） |

### 7.3 智能助手

| 模型 | 表 | 说明 |
| --- | --- | --- |
| `AiModel` | `ai_model` | 供应商与模型配置、加密密钥、密钥使用名单和工具权限上限 |
| `RecordAttachment` | `ims_record_attachment` | 工单或资产到 `SysFile` 的附件关联，按目标记录权限访问 |
| `AiMcpServer` | `ai_mcp_server` | MCP 服务配置（命令是 JSON argv 数组） |
| `AiSkill` | `ai_skill` | Skill 目录配置 |

> `ModelRegistry.NOT_EXPOSED` 里的三个模型（`userRole` / `rolePermission` / `viewConfig`）
> 不出现在菜单和通用接口里。原因是它们的正确性依赖专门逻辑：
> 关联表由 `UserHook` / `RoleController` 统一维护，界面配置必须按用户隔离。
> **新增模型时如果也想隐藏，把它加进这个集合。**

## 8. 建表与改表的边界

`SchemaSync` 在启动时执行，能力刻意做得很窄：

| 能做 | 不能做 |
| --- | --- |
| 建不存在的表 | 改列类型 |
| 给已有表补缺失的列 | 删列 |
| — | 改约束、改索引 |

**为什么这么保守**：自动改类型在 MySQL 上是锁表 + 可能截断数据的高危操作，
在无法确认语义时应拒绝执行而不是猜。

**实践建议**：
- 加字段 → 直接改模型，重启即可；
- 改类型/删列 → 写 SQL 迁移脚本，手工执行，并同步改模型；
- 生产环境把 `ims.sync-schema` 设为 `false`，用脚本管理 DDL。
