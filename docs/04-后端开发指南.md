# 04 · 后端开发指南

> 面向要写服务端代码的人。重点是**约定**：哪些事情有既定做法，为什么不能另起一套。

---

## 1. 包结构与职责

```
com.rabbitc.ims
├── ImsApplication          启动类
├── model/                  ★ 模型（表结构唯一来源）
├── enums/                  模型用到的枚举
├── meta/                   模型注册表、schema 下发
├── service/                通用 CRUD、钩子、审计
├── security/               登录、令牌、密码、拦截器、权限注解
├── ai/                     AI 引擎装配与工具
├── config/                 Spring 配置
├── event/                  应用内事件
├── seed/                   建表与演示数据
├── support/                工具类（Ids 等）
└── web/                    REST 控制器 + 异常处理
```

**依赖方向**：`web → service/security/ai → meta → model → libs`。
`service` 不 import 任何 `web` 包的东西（除了 `ApiException`，它是业务异常，与 HTTP 无关但放在 web 包下）。

## 2. 用 `CrudService` 而不是直接 `sql`

`CrudService` 是所有数据的唯一出入口，它做了四件你单独写一定会漏的事：

1. 权限校验（`requireView / requireEdit / requireDelete`）；
2. 数据范围过滤（`applyScope / visibleRow`）；
3. 字段级权限（`applyBody / toRow`）；
4. 审计（写 `sys_audit_log`）。

```java
// 分页
PageResult page = crud.page(user, "employee", Map.of("page", "1", "size", "20"));

// 单条
Map<String, Object> row = crud.get(user, "employee", id);

// 写
Map<String, Object> created = crud.create(user, "employee", body);
crud.update(user, "employee", id, body);
crud.delete(user, "employee", id);
int n = crud.deleteBatch(user, "employee", List.of(id1, id2));
```

只有一种情况可以直接用 `ModelSession`：**模型内部的关联表维护**（如 `UserHook.syncRoles`）——
因为这些行的权限语义由外层实体决定，走通用 CRUD 反而会被误判。

## 3. 写 ModelHook

```java
@Component
public class XxxHook implements ModelHook {

    private final ModelSession sql;

    public XxxHook(ModelSession sql) { this.sql = sql; }

    @Override
    public boolean supports(Class<?> modelClass) {
        return modelClass == Xxx.class;      // 认领模型
    }

    @Override
    public void beforeCreate(ModelMeta meta, Object entity, Map<String, Object> body, LoginUser user) {
        // 抛 ApiException 即中断操作并回滚
    }

    @Override
    public void afterCreate(ModelMeta meta, Object entity, Map<String, Object> body, LoginUser user) {
        // 实体已插入，主键已可用
    }
}
```

规则：

| 时点 | 实体状态 | 可以做什么 |
| --- | --- | --- |
| `beforeCreate` | 已按请求体赋值，**主键已生成** | 补默认值、校验、改字段 |
| `afterCreate` | 已落库 | 写关联表、发事件 |
| `beforeUpdate` | 已合并请求体，`before` 是改前快照 | 状态机校验、差异检测 |
| `afterUpdate` | 已落库 | 同步关联、发事件 |
| `beforeDelete` | 尚未删除 | 引用检查、防删关键数据 |

注意：

- `beforeUpdate/afterUpdate` 的 `before` 参数是**从库里重新查出来的对象**，可以直接比较字段；
- `after*` 里抛异常会回滚整个事务（`CrudService` 把它们和写操作包在同一个 `sql.transaction` 里）；
- 钩子按 Spring 注入顺序执行，**不要假设某个钩子先跑**；
- `supports()` 里只判断类，不要判断数据内容。

## 4. 事务

```java
sql.transaction(tx -> {
    tx.insert(a);          // 注意用 tx，不是 this.sql
    tx.update(b);
    audit.record(...);
});
```

- `transaction` 里的 lambda 抛任何异常都会回滚；
- **lambda 内必须用 `tx`**，用注入的 `sql` 会跑到事务外；
- 不要在事务里做 HTTP 调用、发消息等慢操作（会长时间持锁）。

`CrudService` 已经包好了 create/update/delete，写钩子时通常不需要自己开事务。

## 5. 异常与错误码

统一异常：`web/ApiException`

```java
throw ApiException.badRequest("客户名称不能为空");    // 400
throw ApiException.unauthorized("账号或密码不正确");  // 401
throw ApiException.forbidden("没有编辑「员工」的权限"); // 403
throw ApiException.notFound("员工 不存在：" + id);     // 404
throw ApiException.notImplemented("暂不支持导出");     // 501
```

`GlobalExceptionHandler` 把它们统一成：

```json
{ "message": "没有编辑「员工」的权限", "status": 403 }
```

| 异常 | HTTP | 说明 |
| --- | --- | --- |
| `ApiException` | 见上 | 业务异常 |
| `CheckerException` | 400 | iPage 模型校验失败 |
| `HttpMessageNotReadableException` | 400 | 请求体不是合法 JSON / 不是 UTF-8 |
| `IllegalArgumentException` | 400 | 参数类型转换失败 |
| `IpagDataAccessException` | 500 | 数据库错误（细节只进日志） |
| `NoResourceFoundException` | 404 | 静态资源缺失（favicon 等），**不记 ERROR** |
| 其它 | 500 | 兜底，日志里带堆栈 |

**约定**：错误信息给用户看，必须是中文、可执行（"密码至少 6 位"而不是"validation failed"）；
数据库错误不把 SQL 原文返回给前端，避免泄露表结构。

## 6. 两个必踩的坑

### 6.1 泛型推断成 `Object`

```java
// ❌ 编译错误：Object 无法转换为 Role
for (Role role : sql.selectList(Query.of(Role.class))) { }

// ✅ 显式指定类型参数
for (Role role : sql.<Role>selectList(Query.of(Role.class))) { }
```

原因：`selectList` 的返回类型取决于目标类型，在 `for` 循环里编译器没有足够信息。
赋值给变量时（`List<Role> list = sql.selectList(...)`）不会有这个问题。

### 6.2 受检异常

`insert` / `update` 抛 `CheckerException`：

```java
try {
    sql.insert(entity);
} catch (CheckerException e) {
    throw ApiException.badRequest(e.getMessage());
}
```

漏掉会编译不过；捕获后吞掉会让用户看到 500。

## 7. 自定义查询

复杂统计可以自己写 SQL，但必须遵守 iPage 的五条约束（见 AGENTS.md 2.1）：

```java
public Map<String, Object> ticketByStatus(LoginUser user) {
    ModelMeta meta = ModelMeta.of(Ticket.class);
    Dialect dialect = sql.dialect();
    String statement = "SELECT " + dialect.quote("ticket_status") + " AS s, COUNT(*) AS c"
                     + " FROM " + dialect.quote(meta.table())
                     + " GROUP BY " + dialect.quote("ticket_status");
    return sql.query(new SqlStatement(statement, List.of()), rs -> {
        Map<String, Object> map = new LinkedHashMap<>();
        while (rs.next()) {
            map.put(rs.getString("s"), rs.getLong("c"));
        }
        return map;
    });
}
```

⚠️ **自定义查询不会自动应用数据范围**。要么在 SQL 里自己加 `dept_id = ?`，
要么明确这是"全局统计"并在接口上限制只有管理员可调。

## 8. 配置项

`config/ImsProperties`（前缀 `ims`）：

| 属性 | 默认 | 说明 |
| --- | --- | --- |
| `ims.secret` | 开发默认值 | 令牌签名密钥，生产必改 |
| `ims.token-ttl-hours` | 12 | 令牌有效期 |
| `ims.seed` | true | 是否写入演示数据（仅在用户表为空时） |
| `ims.sync-schema` | true | 启动时是否同步表结构 |

`ai/AiProperties`（前缀 `ims.ai`）：`enabled / provider / baseUrl / model / apiKey /
maxTokens / contextBudget / allowTools / workDir`。

新增配置的规范：用 `@ConfigurationProperties` + 构造器绑定，并在文档里加一行。

## 9. 日志

- 用 SLF4J，`private static final Logger LOG = LoggerFactory.getLogger(X.class);`
- 业务关键路径用 `INFO`（启动、建表、种子），细节用 `DEBUG`；
- **不要**把密码、令牌、完整请求体打进日志；
- `com.rabbitc.ipage` 默认 `warn`，避免框架的逐条 SQL 刷屏；排查时可临时调到 `debug`：

```yaml
logging:
  level:
    com.rabbitc.ipage: debug
```

## 10. 加一个 REST 接口的模板

```java
@RestController
@RequestMapping("/api/reports")
public class ReportController {

    private final CrudService crud;

    public ReportController(CrudService crud) { this.crud = crud; }

    /**
     * 按部门统计资产金额。
     *
     * @return 部门 → 金额
     */
    @GetMapping("/asset-value")
    @RequirePermission("report:asset:view")
    public Map<String, Object> assetValue() {
        LoginUser user = UserContext.require();
        PageResult page = crud.page(user, "asset", Map.of("size", "200"));
        // ...聚合
        return Map.of("total", 0);
    }
}
```

要点：

1. 路径放在 `/api` 下，自动被 `AuthInterceptor` 拦截；
2. 需要权限点就加 `@RequirePermission`，需要等级就加 `@RequireLevel`；
3. 拿当前用户用 `UserContext.require()`（未登录会抛 401）；
4. 返回 `Map` 或 `record`，不要返回实体（实体里有 `passwordHash` 这类字段）；
5. 方法上写 Javadoc，说明参数与副作用。
