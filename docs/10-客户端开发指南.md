# 10 · 客户端开发指南

> 本文面向**独立客户端**：桌面端、移动端、小程序、命令行工具等。
> `web/` 是随服务端一起发布的管理端；毕业设计通常还需要一个"看得见摸得着"的客户端来演示，
> 两者对接的是**同一套 REST 接口**，权限、数据范围、审计完全一致。
>
> **客户端不是第二个后端。** 它不连数据库、不自己算权限，只做三件事：
> 发请求、按 schema 渲染、把服务端的错误原样告诉用户。

---

## 1. 先选形态

| 形态 | 适合场景 | 开发成本 | 注意点 |
| --- | --- | --- | --- |
| **微信小程序** | 答辩演示最方便，扫码即用 | 低 | 需配置合法域名（本地开发可勾选"不校验合法域名"） |
| **桌面端（Electron / Tauri）** | 需要读本地文件、常驻 | 中 | 渲染进程访问 `http://localhost:8080`，CORS 已被服务端放开 |
| **移动端（Android / iOS 原生）** | 要走系统能力（相机、推送） | 中高 | 无 CORS 概念；令牌存 Keystore / Keychain |
| **命令行 / 脚本** | 批量导入、定时任务 | 低 | 直接 `curl` 或几十行 Python，最适合做"数据初始化工具" |
| **另一套 Web 前端** | 想做"学生端 + 管理端"两套界面 | 中 | 复用同一套接口，只是页面不同 |

> 毕业设计常见组合是 **小程序（学生/员工端）+ Web 管理端（管理员）**。
> 两者共用 `admin` 之外的另一批账号，正好演示 RBAC 的差异。

**本文以微信小程序为主线**给出可运行代码，其它形态在第 8 节给差异说明。

## 2. 与后端的契约

### 2.1 基础

| 项 | 值 |
| --- | --- |
| Base URL | `http://<主机>:8080` |
| 前缀 | 所有业务接口在 `/api` 下 |
| 编码 | UTF-8；请求体 `Content-Type: application/json; charset=utf-8` |
| 认证 | `Authorization: Bearer <token>` |
| 错误体 | `{"message": "中文提示", "status": 403}` |
| 主键 | UUID 字符串（36 位），**不要当数字处理** |

### 2.2 免认证接口

只有两个：

- `POST /api/auth/login`
- `GET /api/health`

其余全部需要令牌。客户端不要在本地维护"哪些接口免登录"的清单，统一走请求封装即可。

### 2.3 错误约定

| 状态码 | 客户端应该做什么 |
| --- | --- |
| `400` | 表单校验失败，把 `message` 显示在表单上方 |
| `401` | 令牌失效 → 清本地令牌 → 跳登录页（带 `redirect`） |
| `403` | 无权限 → 提示 `message`，**不要重试** |
| `404` | 记录已被删除 → 提示并刷新列表 |
| `500` / `502` | 服务端故障 → 提示"服务异常"并提供重试 |
| 网络失败 | 提示"无法连接服务端"，可重试 |

**`message` 是直接给用户看的中文**（例如"没有编辑「员工」的权限"），
不要在客户端改写成"操作失败"——那句提示比你自己写的更有用。

## 3. 认证流程

```
① 登录  POST /api/auth/login {username, password}
        ← {token, user:{id, username, name, level, dataScope, isAdmin, permissions[]}}
② 存令牌（小程序 storage / 桌面 keychain / 移动端 Keystore）
③ 后续请求带 Authorization: Bearer <token>
④ 任一请求 401 → 清令牌 → 回登录页
```

### 3.1 三个必须知道的行为

1. **令牌 12 小时过期**（`ims.token-ttl-hours`），过期表现为 401。
2. **改密码会让旧令牌立即失效**：`POST /api/auth/password` 成功后会返回**新令牌**，
   客户端必须替换本地令牌，否则下一个请求就 401。
3. **令牌里没有权限**。权限是服务端每次请求现查的，所以管理员改了权限，
   客户端**重新拉一次 `/api/auth/me` 或 `/api/models/{key}/schema`** 就能看到变化，
   不需要重新登录。

### 3.2 令牌存哪里

| 平台 | 建议 | 不要用 |
| --- | --- | --- |
| 小程序 | `wx.setStorageSync` | — |
| 桌面 | 系统凭据库（keytar 等） | `localStorage` 明文（可接受但要知道风险） |
| Android | `EncryptedSharedPreferences` | 普通 SharedPreferences |
| iOS | Keychain | UserDefaults |

## 4. 请求层封装（客户端唯一的核心代码）

所有客户端都要写这层，写对了后面全是页面。**要求：统一加令牌、统一处理 401、统一超时、统一错误文案。**

### 4.1 微信小程序版

`utils/request.js`：

```js
// 开发时用本机 IP，真机调试不能写 127.0.0.1（那是手机自己）
const BASE_URL = 'http://192.168.1.10:8080'
const TOKEN_KEY = 'ims_token'

/**
 * 调用后端接口。
 * @param {string} path   以 / 开头的路径，不含 /api
 * @param {object} options { method, data, params, timeout }
 * @returns {Promise<any>} 响应体
 */
function request(path, options = {}) {
  const { method = 'GET', data, params, timeout = 15000 } = options
  const token = wx.getStorageSync(TOKEN_KEY)

  let url = BASE_URL + '/api' + path
  if (params) {
    // 空值不发；中文必须 encodeURIComponent，否则服务端收到乱码
    const query = Object.entries(params)
      .filter(([, value]) => value !== '' && value !== null && value !== undefined)
      .map(([key, value]) => `${encodeURIComponent(key)}=${encodeURIComponent(value)}`)
      .join('&')
    if (query) url += '?' + query
  }

  return new Promise((resolve, reject) => {
    wx.request({
      url,
      method,
      timeout,
      header: Object.assign(
        { 'Content-Type': 'application/json' },
        token ? { Authorization: 'Bearer ' + token } : {}
      ),
      data,
      success(res) {
        const ok = res.statusCode >= 200 && res.statusCode < 300
        if (ok) {
          resolve(res.data)
          return
        }
        if (res.statusCode === 401) {
          // 令牌失效：清掉并回登录页，由登录页重新拿 redirect
          wx.removeStorageSync(TOKEN_KEY)
          wx.reLaunch({ url: '/pages/login/login' })
        }
        const message = (res.data && res.data.message) || `请求失败（${res.statusCode}）`
        reject(Object.assign(new Error(message), { status: res.statusCode }))
      },
      fail(err) {
        reject(new Error('无法连接服务端，请确认后端已启动：' + (err.errMsg || '')))
      }
    })
  })
}

module.exports = { request, BASE_URL, TOKEN_KEY }
```

### 4.2 桌面 / Node 版（fetch，逻辑相同）

```js
async function request(path, { method = 'GET', body, params } = {}) {
  const url = new URL('/api' + path, BASE_URL)
  for (const [k, v] of Object.entries(params || {})) {
    if (v !== '' && v != null) url.searchParams.set(k, v)
  }
  const token = getToken()
  const res = await fetch(url, {
    method,
    headers: {
      Accept: 'application/json',
      ...(body !== undefined ? { 'Content-Type': 'application/json; charset=utf-8' } : {}),
      ...(token ? { Authorization: `Bearer ${token}` } : {})
    },
    body: body === undefined ? undefined : JSON.stringify(body)
  })
  const text = await res.text()
  const payload = text ? JSON.parse(text) : null
  if (!res.ok) {
    if (res.status === 401) clearToken()
    throw Object.assign(new Error(payload?.message || `请求失败（${res.status}）`), { status: res.status })
  }
  return payload
}
```

> 这和服务端仓库里 `web/src/api/http.js` 是同一套思路，可以直接对照看。

## 5. schema 驱动：客户端不写死字段

### 5.1 为什么要这样

如果客户端把"工号、姓名、部门"写死在页面里，那么：
- 服务端加一个字段，客户端要发版；
- 不同模型要写不同页面；
- 权限一变，页面就错。

改成读 schema 后：**一个列表页服务所有模型**，加字段零改动。

### 5.2 拿 schema

```http
GET /api/models/{key}/schema
```

```json
{
  "key": "employee",
  "name": "员工",
  "permissions": { "view": true, "create": true, "edit": true, "delete": false },
  "fields": [
    { "name": "empNo", "text": "工号", "type": "STRING", "table": true, "form": true, "order": 2 },
    { "name": "dept",  "text": "部门", "type": "ASSOCIATION_MODEL", "table": true, "form": false, "order": 4 },
    { "name": "status","text": "状态", "type": "ENUM", "options": { "ENABLED": "启用" }, "table": true, "form": true }
  ]
}
```

关键字段：

| 字段 | 用途 |
| --- | --- |
| `permissions.view/create/edit/delete` | 按钮显隐（**只影响显示，不代替服务端校验**） |
| `fields[].table` | 是否作为列表列 |
| `fields[].form` | 是否作为表单项 |
| `fields[].order` | 顺序 |
| `fields[].type` | 决定用什么控件（见下表） |
| `fields[].options` | 枚举或关联下拉的选项 `{值: 中文}` |
| `fields[].required / maxLength / pattern` | 前端即时校验 |

### 5.3 类型 → 控件映射

| `type` | 控件 |
| --- | --- |
| `STRING` | 输入框（`maxLength > 120` 用多行） |
| `NUMBER` | 数字输入 |
| `DATE` | 日期选择器（值格式 `yyyy-MM-dd` 或 `yyyy-MM-dd HH:mm:ss`） |
| `BOOLEAN` | 开关 |
| `ENUM` | 下拉，选项来自 `options` |
| `ASSOCIATION_ID` | 下拉，选项来自 `options`（值是被关联表的主键） |
| `PASSWORD` | 密码框（编辑时留空表示不改） |
| `MULTI_SELECT` | 多选（当前只有用户角色用到） |
| `MODEL_ID` / `ASSOCIATION_MODEL` / `AGGREGATION` | **不渲染表单项**；`ASSOCIATION_MODEL` 只在列表里显示 `label` |

### 5.4 行数据怎么显示

列表接口返回的行：

```json
{
  "id": "95131f9c-4be7-43d6-bb18-7dcb59c73be1",
  "_display": "周然",
  "dept": { "id": "8ea8...", "label": "财务部" },
  "status": "ENABLED",
  "statusText": "启用"
}
```

显示规则（照抄即可）：

```
关联列  → row[field.name].label
枚举列  → row[field.name + 'Text']
布尔列  → row[field.name] ? '是' : '否'
空值    → '—'
其它    → row[field.name]
```

**不要**自己把 `deptId`（UUID）显示出来，用户看不懂；也用 `label` 而不是再查一次关联表。

## 6. 页面实现

### 6.1 登录页

```js
// pages/login/login.js
const { request, TOKEN_KEY } = require('../../utils/request')

Page({
  data: { username: '', password: '', loading: false, error: '' },

  onInput(e) {
    this.setData({ [e.currentTarget.dataset.field]: e.detail.value })
  },

  async submit() {
    this.setData({ loading: true, error: '' })
    try {
      const result = await request('/auth/login', {
        method: 'POST',
        data: { username: this.data.username, password: this.data.password }
      })
      wx.setStorageSync(TOKEN_KEY, result.token)
      wx.setStorageSync('ims_user', result.user)
      wx.switchTab({ url: '/pages/list/list' })
    } catch (e) {
      this.setData({ error: e.message })
    } finally {
      this.setData({ loading: false })
    }
  }
})
```

> 验证普通员工权限时，先由超级管理员在测试库创建员工登录账号并分配普通员工角色。

### 6.2 通用列表页

```js
// pages/list/list.js
const { request } = require('../../utils/request')

Page({
  data: {
    models: [],        // 可选模型（来自 /api/nav）
    key: 'employee',
    schema: null,
    columns: [],       // schema 里 table=true 的字段
    rows: [],
    page: 1,
    pages: 0,
    kw: '',
    canCreate: false
  },

  onLoad() {
    this.loadModels()
    this.loadSchema()
  },

  async loadModels() {
    const nav = await request('/nav')
    this.setData({ models: nav })
  },

  async loadSchema() {
    const schema = await request(`/models/${this.data.key}/schema`)
    this.setData({
      schema,
      columns: (schema.fields || []).filter((f) => f.table),
      canCreate: !!schema.permissions.create
    })
    this.loadRows()
  },

  async loadRows() {
    const result = await request(`/models/${this.data.key}`, {
      params: { page: this.data.page, size: 20, kw: this.data.kw }
    })
    this.setData({ rows: result.rows, pages: result.pages })
  },

  onSearch(e) {
    this.setData({ kw: e.detail.value, page: 1 }, () => this.loadRows())
  },

  nextPage() {
    if (this.data.page >= this.data.pages) return
    this.setData({ page: this.data.page + 1 }, () => this.loadRows())
  },

  openDetail(e) {
    const row = e.currentTarget.dataset.row
    wx.navigateTo({ url: `/pages/detail/detail?key=${this.data.key}&id=${row.id}` })
  }
})
```

```xml
<!-- pages/list/list.wxml -->
<view class="page">
  <view class="toolbar">
    <input placeholder="搜索" bindinput="onSearch" />
  </view>

  <view class="row head">
    <text wx:for="{{columns}}" wx:key="name" class="cell">{{item.text}}</text>
  </view>

  <view class="row" wx:for="{{rows}}" wx:key="id" data-row="{{item}}" bindtap="openDetail">
    <text wx:for="{{columns}}" wx:for-item="col" wx:key="name" class="cell">
      <!-- 关联列取 label，枚举列取 xxxText，其余直接取值 -->
      <block wx:if="{{col.type === 'ASSOCIATION_MODEL'}}">{{item[col.name].label || '—'}}</block>
      <block wx:elif="{{col.type === 'ENUM'}}">{{item[col.name + 'Text'] || '—'}}</block>
      <block wx:else>{{item[col.name] === null || item[col.name] === '' ? '—' : item[col.name]}}</block>
    </text>
  </view>

  <view class="pager">
    <button size="mini" bindtap="prevPage">上一页</button>
    <text>{{page}} / {{pages}}</text>
    <button size="mini" bindtap="nextPage">下一页</button>
  </view>
</view>
```

> `wx:for` 里动态下标 `item[col.name]` 在小程序中**可用**（WXML 支持中括号取值），
> 这是 schema 驱动能成立的关键。

### 6.3 新增/编辑

表单字段来自 `schema.fields.filter(f => f.form)`，提交时**只发送 `form=true` 且非空的字段**：

```js
const payload = {}
for (const field of formFields) {
  const value = this.data.values[field.name]
  if (field.type === 'PASSWORD') {
    if (value) payload.password = value      // 编辑时留空表示不改
    continue
  }
  if (value === '' || value === null || value === undefined) continue
  payload[field.name] = value                // 主键/外键都是字符串，保持原样
}

await request(`/models/${key}`, { method: 'POST', data: payload })
```

编辑时把 `payload` 发给 `PUT /api/models/{key}/{id}`，**服务端只更新出现的字段**，
所以"只传改动的字段"是合法且推荐的做法。

## 7. 客户端常犯的五个错

### 7.1 把 UUID 当数字

```js
Number('95131f9c-...')   // NaN
parseInt(id)             // NaN
```
主键、`deptId`、`assigneeId`、`roleIds` 全部按**字符串**处理。
这是从自增主键系统迁移过来时最容易踩的坑（`web/` 就曾经这么错过）。

### 7.2 自己在客户端过滤数据范围

错。数据范围（全部 / 本部门 / 仅本人）由服务端在 SQL 层施加，
客户端拿到的 `total` 已经是过滤后的数量。客户端再过滤一遍只会让数字对不上。

### 7.3 用本地缓存的权限决定要不要发请求

`permissions` 只用于**显示/隐藏按钮**。真正的判定在服务端，而且权限可能在你缓存的这一刻被改掉。
正确做法：进页面重新拉 schema；请求被 403 就按 403 提示。

### 7.4 中文参数不编码

```
❌ /api/models/employee?kw=苏
✅ /api/models/employee?kw=%E8%8B%8F
```
`wx.request` 的 `data` 会自动序列化，但 **URL 里的 query 不会**——手动 `encodeURIComponent`。

### 7.5 把 AI 接口当普通接口用

`POST /api/ai/chat` 是**同步阻塞**的，模型思考 + 工具调用可能 20～60 秒。
客户端超时至少设 60 秒，并且要有一个"正在思考"的加载态，否则用户会以为卡死。

## 8. 其它形态的差异

### 8.1 桌面端（Electron / Tauri）

- 渲染进程直接 `fetch('http://127.0.0.1:8080/api/...')`，服务端已放开 `http://localhost:*` 与 `http://127.0.0.1:*` 的 CORS；
- 打包后 `file://` 发起请求时 `Origin` 为 `null`，若遇到 CORS 被拒，用主进程代理转发，或把窗口加载本地 http 服务；
- 令牌存系统凭据库（keytar / tauri-plugin-store + 加密）；
- 好处：可以直接读写本地 Excel/CSV，做"批量导入"演示。

### 8.2 Android / iOS 原生

- 没有 CORS，直接请求即可；
- 网络库（OkHttp / URLSession）统一加 `Authorization` 拦截器；
- 令牌进 Keystore / Keychain；
- 注意 `http://` 明文请求在 Android 9+ 默认被禁，需要 `network_security_config` 放行内网地址（或用 HTTPS）。

### 8.3 命令行 / Python 脚本

仓库自带一个**可直接运行**的参考客户端：`clients/cli/ims_cli.py`（零依赖，只用 Python 标准库）。
它把本文的核心约定都实现了一遍，可以当模板抄：

```bash
cd clients/cli

python ims_cli.py login --user admin --password 123456
python ims_cli.py models                       # 列出可访问的模型
python ims_cli.py schema employee              # 看字段定义
python ims_cli.py list employee --kw 苏 --size 5
python ims_cli.py list employee --with-id      # 带上主键，便于接下面的命令
python ims_cli.py show employee <uuid>
python ims_cli.py create employee --set empNo=E2001 --set name=新员工
python ims_cli.py update employee <uuid> --set position=技术总监
python ims_cli.py delete employee <uuid>       # 会二次确认，加 --yes 跳过
```

它做了这几件事，值得在自己客户端里照做：

| 实现点 | 代码位置 |
| --- | --- |
| 令牌缓存到 `~/.ims_token`（0600 权限） | `save_token / load_token` |
| 统一带 `Authorization`、统一把 401 提示"重新登录" | `api()` |
| 中文 query 用 `urlencode(encoding='utf-8')` | `api()` |
| 请求体 `ensure_ascii=False` 发真中文 | `api()` |
| 列由 schema 推导，不写死字段 | `columns_from_schema()` |
| 枚举取 `xxxText`、关联取 `label` | `print_table()` |
| 中文列宽按双宽字符对齐 | `print_table()` 里的 `width()` |

> 也可以把它当"演示数据灌库工具"：答辩前一条命令造数据，比手点快得多。
>
> 如果只要一个最小脚本，下面这段就够了：

```python
import json, urllib.request, urllib.parse

BASE = "http://127.0.0.1:8080"

def call(method, path, body=None, token=None):
    req = urllib.request.Request(BASE + "/api" + path, method=method)
    req.add_header("Content-Type", "application/json; charset=utf-8")
    if token:
        req.add_header("Authorization", "Bearer " + token)
    data = json.dumps(body, ensure_ascii=False).encode("utf-8") if body is not None else None
    with urllib.request.urlopen(req, data) as resp:
        return json.loads(resp.read().decode("utf-8"))

token = call("POST", "/auth/login", {"username": "admin", "password": "123456"})["token"]
print(call("GET", "/models/employee?kw=" + urllib.parse.quote("苏"), token=token)["total"])
```

### 8.4 另一套 Web 前端

复制 `web/` 作为起点即可，接口完全复用。若要与管理端区分，只改：

## 9. 兼容性：模型演进时客户端怎么办

| 服务端变化 | 客户端表现 | 需要改客户端吗 |
| --- | --- | --- |
| 新增字段 | schema 多一项，列表/表单自动多一列 | **不需要** |
| 字段改中文名 | 表头跟着变 | 不需要 |
| 调整字段顺序（`order`） | 顺序跟着变 | 不需要 |
| 新增模型 | `/api/nav` 多一项 | 若菜单是渲染的，不需要 |
| 字段改类型（如 STRING→NUMBER） | 控件类型变了 | 不需要（映射表已覆盖） |
| 删除模型 | nav 少一项 | 不需要 |
| 主键类型变更 | 全部失效 | **需要**（本项目已固定 UUID，不会再变） |

这就是 schema 驱动的价值：**加字段不客户端发版**。

### 7.6 在一次请求中接收多条消息与工具事件

网页助手使用 `POST /api/ai/chat/stream`，请求体仍为
`{"message":"查询并处理", "allowTools":true}`，认证仍使用 Bearer token 和 `ai:use` 权限。
响应为 `application/x-ndjson`，每行一个完整 JSON 对象；应增量解码 UTF-8，网络分块不等于消息边界。

```json
{"type":"assistant","text":"先查询相关数据"}
{"type":"tool","audit":{"name":"demo_query","arguments":"{}","result":{"ok":true,"result":{}}}}
{"type":"assistant","text":"处理完成"}
{"type":"done"}
```

模型使用 `assistant_reply`（参数 `text`）发送消息，之后仍可调用任意已授权工具，
可跨多个 MCP 服务、多轮调用；使用 `assistant_end`（空参数对象）结束本次处理。
每次消息发送和结束也记录工具审计，因此会有对应的 `tool` 事件。
若同批调用在结束工具之后仍有其他工具，这些调用会被跳过并记录失败，避免结束后继续修改数据。
普通的无工具调用模型回复也作为本次处理结束，以兼容未启用工具的场景。

收到 `done` 才表示正常结束。`error` 事件包含 `message`，表示本次处理失败；
若连接断开且未收到 `done`，应提示中断。保留已收到消息及工具结果，不自动重试写操作。
结束只结束当前请求，不清空聊天历史，用户可以继续发送下一条输入。
旧的 `POST /api/ai/chat` 继续返回最后一条回复及本次请求的工具审计，
完整历史仍由 `/api/ai/history` 提供。

离线回归入口：`node --test web/test/chat-stream.test.mjs`。
核心工具循环回归位于 `libs/embed-ai-chat/src/test/java/io/embedai/ConversationEventsTest.java`，
可与主类一起使用 Gson 依赖编译后运行其 `main`，无需真实模型或 MCP 服务。
