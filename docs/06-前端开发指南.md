# 06 · 前端开发指南

> 前端只有 16 个文件，核心思想一条：**页面由服务端 schema 驱动，不在前端写死字段**。
> 所以加字段不用改前端，加交互才需要。

---

## 2. 请求层约定

```js
import { api } from '../api/http'

const page = await api('/models/employee', { params: { page: 1, size: 20, kw: '陈' } })
await api('/models/employee/' + id, { method: 'PUT', body: { position: '总监' } })
```

- `path` 以 `/` 开头，`/api` 前缀自动加；
- `params` 里 `undefined / null / ''` 会被自动跳过（不用手写条件拼接）；
- 非 2xx 抛 `ApiError`，带 `status`；`401` 会自动清除本地令牌；
- 网络不通时抛 `ApiError('无法连接服务端…', 0)`。

错误处理范式：

```js
try {
  await api(...)
  toast('保存成功')
} catch (e) {
  toastError(e.message)      // 服务端返回的中文提示已足够可读
}
```

**不要**在 catch 里改写文案，服务端的提示（"没有编辑「员工」的权限"）比"操作失败"有用得多。

## 3. 登录状态

```js
import { auth, can } from '../stores/auth'

auth.user.name        // 姓名
auth.user.level       // 等级 0–4
auth.user.dataScope   // ALL / DEPT / SELF
auth.user.isAdmin     // 服务端算好的布尔量
can('system:role:manage')   // 权限点判断（isAdmin 恒 true）
```

- 令牌存 `localStorage['ims_token']`；
- `main.js` 启动时调 `loadMe()`，失败则跳登录；
- **前端权限判断只用于"显示/隐藏"，不是安全边界**——所有请求服务端都会再判一次。

## 4. 通用列表页 `ModelView.vue`

路由 `/m/:key`，所有模型共用。它做的事：

1. `GET /api/models/{key}/schema` 拿字段定义与权限布尔量；
2. 按 `field.table` 决定显示哪些列，`field.order` 决定顺序；
3. 关键字搜索用 `schema.searchFields`；
4. 多条件筛选：字段 + 操作符 + 值，拼成 `f_{name}` / `op_{name}`；
5. 排序：点表头 → `sort` / `order`；
6. 分页：`page` / `size`；
7. 勾选批量删除 → `POST /batch-delete`；
8. 列设置（显隐、每页条数）→ `PUT /api/views/{key}`，按用户持久化。

**扩展它的正确方式**：优先用 schema（改模型注解），而不是改这个文件。
只有当"所有模型都需要"的新能力（比如导出）才动它。

## 5. schema 驱动表单 `DataForm.vue`

传 `schema` + `row`（编辑时）+ `mode`，组件自己渲染并校验。

| `field.type` | 渲染成 |
| --- | --- |
| `STRING` | `<input>`；`maxLength > 120` 或字段名是 `description/remark` 时用 `<textarea>` |
| `NUMBER` | `<input type="number">` |
| `PASSWORD` | `<input type="password">`，编辑时留空表示不改 |
| `DATE` | `<input type="date">` / `datetime-local` |
| `BOOLEAN` | 复选框 |
| `ENUM` | `<select>`，选项来自 `field.options` |
| `ASSOCIATION_ID` | `<select>`，选项来自 `field.options`（被关联表的 id → 显示名） |
| `MULTI_SELECT` | 多选 chips（用于用户角色） |
| `AGGREGATION` / `MODEL_ID` / `ASSOCIATION_MODEL` | 不渲染 |

前端校验：`required`（含 `requiredOnCreate`）、`maxLength`、`pattern`。
**服务端会再校验一次**，前端只是即时反馈。

### 主键是 UUID 的注意点

表单里所有主键/外键值都是**字符串**：

```js
values[field.name] = String(raw)     // 关联外键
payload[field.name] = value          // 原样传字符串
```

写成 `Number(uuid)` 会得到 `NaN`，表单会静默失效。这是从自增主键迁移过来时最容易踩的坑。

## 6. 加一个自定义页面

```js
// 1. web/src/views/ReportView.vue
<script setup>
import { ref, onMounted } from 'vue'
import { api } from '../api/http'

const rows = ref([])
onMounted(async () => {
  rows.value = await api('/reports/asset-value')
})
</script>

<template>
  <div class="page">
    <h2>资产统计</h2>
    <table class="data">...</table>
  </div>
</template>
```

```js
// 2. router.js
{ path: '/report', component: () => import('./views/ReportView.vue'), meta: { title: '资产统计' } }
```

```js
// 3. AppLayout.vue 的导航里加一项，用 can() 控制显隐
{ to: '/report', label: '资产统计', icon: 'fa-chart-bar', show: () => can('report:asset:view') }
```

**先问自己三个问题**，能省掉一个页面：
1. 只是列不同？→ 用列设置；
2. 只是默认排序不同？→ 改 `schema.defaultSort`（`MetaService`）；
3. 只是少几个字段？→ 用字段的 `look` 或 `lookPermission`。

## 7. 样式与主题

所有颜色走 CSS 变量（`styles.css` 顶部）：

```css
:root {
  --bg; --panel; --border; --border-strong; --text; --muted;
  --primary; --danger; --danger-weak; --success; --warn;
}
[data-theme="dark"] { /* 覆盖同名变量 */ }
```

- 切换主题：`document.documentElement.dataset.theme = 'dark'`，同时写 `localStorage['ims_theme']`；
- 通用类：`.card` `.btn(.primary/.ghost/.sm)` `.input` `.select` `.textarea` `.badge(.grey/.green/.red)` `table.data` `.modal` `.toast`；
- **不要在组件里写死颜色**，深色模式会漏掉。

## 8. 路由

`createWebHashHistory`（URL 形如 `/#/m/employee`）。选 hash 的原因：单端口部署时不需要服务端 SPA 回退配置，
后端 `static/` 直接托管 index.html 即可。

路由表：

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/login` | LoginView | 免登录 |
| `/dashboard` | DashboardView | 默认首页 |
| `/m/:key` | ModelView | 任意模型 |
| `/permissions` | PermissionsView | 需管理员 |
| `/ai` | AiView | 需 `ai:use` |
| `/profile` | ProfileView | 个人设置 |

守卫在 `router.js` 里：未登录跳 `/login?redirect=...`，已登录访问 `/login` 跳 `/dashboard`。

## 9. 构建与联调

```bash
cd web
npm install
npm run dev      # http://127.0.0.1:5173，/api 代理到 127.0.0.1:8080
npm run build    # 产物在 dist/，拷到 server/src/main/resources/static 后随 jar 发布
```

`vite.config.js` 里已经配好代理，开发时不需要处理跨域。
生产环境前后端同源（同一个 8080），也不需要 CORS。

## 10. 前端测试现状

目前**没有自动化测试**，靠 `npm run build`（能发现语法/引用错误）+ 手工点检。
要补的话，优先级：

1. `DataForm` 的校验与提交载荷（纯函数，最好测）；
2. `ModelView` 的查询参数拼装；
3. 端到端（Playwright）：登录 → 某模型增删改查 → 权限 403。
